# REQ-0008 提改进建议前先证伪

## 问题与目标

复审常产出"看似有理有据、实际不成立"的建议。现有 §3 的"**带证据**"防不住——一个错误建议也能附上一条弱证据。需要把动作从"**找支持证据**"升级为"**先试着推翻**"：每条候选意见先问"哪条命令、哪段原文能最快推翻它？"，跑完再写；被推翻的丢弃。并让筛选**可见**（报告淘汰数）。

## 触发与分支

- 复审 Step 8 产出改进意见时。
- 用户说"给改进建议 / 评审 / 优化这个技能"。

## 行为与步骤

1. `reviewing-skills.md` **§3**：把"带证据"换成"**先证伪，再提**"——
   - 先问"**哪条命令、哪段原文能最快推翻它？**"，**跑完再写**，被推翻的丢弃；
   - 跑不了检查的标「待验证」，**不进正式意见列表**；
   - 依据写"**我看到 X**"，不写"我认为 X"。
   并新增"**报告淘汰数**"：写明"N 个候选，M 个通过，其余被证伪"。
2. `reviewing-skills.md` **Step 8 完成判据**：要求意见已过"先证伪"、并附淘汰数。
3. 不新增文件、不新增脚本。

## 脚本与资源

- 只改 `references/reviewing-skills.md`。

## 降级与边界

- 主观判断（"这个措辞更清楚"）不必硬凑命令 → 标「待验证」。
- 主观**比较**（哪版更好）走 `subagents.md` 的 comparator（A/B），**不适用**证伪。
- 与 `SKILL.md` 共用原则的"证据优先"不重复：那是原则，本处是操作步骤。
