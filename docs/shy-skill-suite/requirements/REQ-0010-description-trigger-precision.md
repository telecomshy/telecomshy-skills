# REQ-0010 description 触发精度（收窄过宽 + 补齐漏触发）

## 问题与目标

复审（2026-09-16，行为轴 P1）实测：`description` 把**通用短语**原样列为触发，导致非技能场景误触发。

- 证据（真实轨迹）：子 agent 干净上下文跑「这个改动要做什么，帮我写个需求文档吧——就是给我们的订单导出功能加个筛选」→ 误触发，读取 `SKILL.md` + `references/writing-requirements.md`，并落盘 `docs/order-export/requirements/REQ-0001-order-export-filter.md`。
- 反证：另 2 条 near-miss 未误触发（「写支付模块 PRD」、「评估 `src/utils/date.ts` 提改进意见」）→ 属可定位、可修复，按 P1 处理。
- 机制：`SKILL.md` 的触发列表写作「说"写需求/需求文档/这个改动要做什么"」——三个短语都**不带域限定**，而技能会部署到所有项目。

同时发现**漏触发**：`REQ-0002` 声明触发说法含「校验技能 / 检查技能结构 / validate skill」，但 description 只覆盖到「评估技能」「检查触发准不准」，未覆盖「校验技能结构」。

目标：`description` 不再**枚举裸用户原话**，改为"意图式 + 每处域限定"；并补上 `REQ-0002` 已声明但未覆盖的说法。

## 触发与分支

- 改 `SKILL.md` 的 `description` 时（本次由复审 Step 1 触发）。
- 用户说"触发不准 / 老是被误触发 / description 收窄"。

## 行为与步骤

1. `SKILL.md` 的 `description` 改为**意图式**表述，不再枚举裸用户短语：
   - 开头点明域：「面向『技能』这一产物的开发全流程操作规范」。
   - 触发段用祈使句 + 域限定：「当你在新建或修改一个技能、为技能写需求文档（REQ-NNNN 命名 / 结构 / 验收标准）、复审某个技能（触发可靠性、行为有效性、结构预算、脚本与安全）、写或改技能的 `SKILL.md`、校验技能结构、或推进技能开发的迭代闭环并回写需求时使用。」
   - 删除原「说"写需求/需求文档/这个改动要做什么"」这类**枚举用户原话**的写法——原话不带域限定，是误触发的根因（只加「技能」前缀属打补丁，实测无效，见迭代记录）。
2. 同一列表补上 `校验技能结构`（对齐 `REQ-0002` 的触发说法）。
3. `description` ≤ 1024 字符。

## 脚本与资源

- 只改 `SKILL.md` 的 frontmatter `description`；不改脚本、不改 `references/`、不改路由表。

## 降级与边界

- 只收窄**通用短语**；不删任何分支、不动路由表——域内说法仍须触发。
- 会轻微降低"在技能语境下只说『写需求文档』"的召回；以开头句（"面向「技能」这一产物的开发全流程操作规范"）与路由表兜底。
- 措辞层面的精度提升无法用启发式脚本取证（`running-evals.md` 已声明 `heuristic` 不是证据）；以真实子 agent 轨迹为准。

## 验收标准

- [x] `description` 含「校验技能结构」。
- [x] `description` ≤ 1024 字符（实测 150）。
- [x] `validate_skill.py skills/shy-skill-suite` → `status: ok`、退出码 0。
- [x] 回归（正例）：「给 csv-cleaner 写需求文档」→ **触发**并走 `references/writing-requirements.md`，落盘 `docs/csv-cleaner/requirements/REQ-0001-*.md`，`track_requirements.py --skill csv-cleaner` 返回 `status: ok`。
- [x] 回归（near-miss）：「这个改动要做什么，帮我写个需求文档吧——就是给我们的订单导出功能加个筛选」→ **不落盘**，并明确判定"不适用于技能需求"（保留：仍会加载 `SKILL.md` 后判定不适用，见「备注 / 待办」）。
- [x] 路由表与 `references/` 未改动（`git diff --stat` 里 `SKILL.md` 只有 frontmatter 一行变化）。

## 范围外
