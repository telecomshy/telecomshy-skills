# REQ-0062 复审脆弱性治理

## 问题与目标

`iteration-7` 复审又出 10 条（1 P1 + 9 P2），用户追问"为什么修复了还越查越多"。溯源（HEAD vs 现状）显示：**存量老洞 5、契约台账过期 1、上轮修复涟漪 4**；上轮 9 条修复零回归。问题不在"循环"，在**三个发生器**：

1. **修复的涟漪没在当轮付清**——一次代码改动波及文档 / 文案 / 测试，只改代码，下轮扫出 3 条。
2. **契约双份维护**（技能文件 + REQ 验收文字），同步全靠人 → 过期验收每轮产出 1–3 条。
3. **自指检查天生脆弱**——`converged-mechanical` 查自己的源码字符串。

另补两条（本轮新增）：
4. **复审面不缩反涨**——语义验收每轮全读，稳定项不被冻结。
5. **缺材料性门槛**——不影响使用的文字问题也报成 finding。

目标：让复审**只报"不修会导致做错事 / 做不成事"的问题**；其余当轮结清；复审面随轮次收缩；脆弱性有机械可判的终点。

## 触发与分支

- 复审 Step 8 汇总与分拣；实现路阶段 2 收尾。
- 用户说"怎么越查越多 / 检查太细 / 不影响使用就别修"。

## 行为与步骤

1. **涟漪付清**（`lifecycle.md` 阶段 2 完成判据）：改行为时当轮同时完成——① 订正受影响契约文本（REQ 验收 / 技能文档）；② 新行为加 / 更新回归检查；③ 删改前查引用（已有）。
2. **材料性门槛**（`reviewing-skills.md` Step 8）：候选只有"**不修会让用户 / agent 做错事或做不成事**"才算 finding（行为 / 触发 / 接口 / 安全 / 可用性）。**台账类**（过期验收文字但检查仍绿、提示文案偏差、重复、措辞、死代码、自洽计数）→ `cleanup.md`，**发现即修、不进 findings**。
3. **Step 3 的"文档-实现不一致"收窄**：只在**会误导 agent 行为**（`description` / 路由 / 接口 / 范围声明）时算 finding；纯文字落后走台账。
4. **自指检查行为化**：`converged-mechanical` 改为"造带债 / 达标两个最小仓库，断言 `converged` 真假与退出码"；今后新 meta 检查优先行为化，纯子串检查须标注为台账类。
5. **语义集做减法**（Step 8）：稳定 ≥2 轮、且内容已被技能文件或检查覆盖的语义验收 → 标 `（episode）` 冻结；下轮复审面随之缩小。
6. **脆弱性收敛判据**（Step 8）：一次复审 **0 P0/P1** 且 **0 条"上轮改动涟漪"类 finding**（新 finding 均不落在上轮改过的文件 / 契约上）→ **脆弱性已解**；只记结论、不排下一轮，直到真实失败 / 用户显式要求再开。
