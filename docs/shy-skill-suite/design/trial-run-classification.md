## 2. 三个关键发现

### 发现 1：39 条标准在断言**别的 REQ 文档**，不是技能当前行为

例：

- `REQ-0030`：「`REQ-0025` 的 frontmatter 含 `superseded_by: REQ-0030`」— `check:req0030-req0025-superseded`
- `REQ-0042`：「`REQ-0026` 验收判据不含写死的"= 8"」— `check:req0042-count-free`
- `REQ-0046`：「`REQ-0041` 与 `REQ-0043` 含 `superseded_by: REQ-0046`」— `check:req0046-superseded`
- `REQ-0031` 整份（12 条）都是「把 `REQ-XXXX` 的验收改成……」

**这 39 条就是"每次复审都在改 REQ"的直接来源。** 按新模型它们全是 **episode**——一次性文档订正，做完冻结，**永不重扫**。

### 发现 2：现有的 `check:` 大多是**文档措辞存在性**检查，不是行为

61 条可执行项里，只有约 10 条在测**真行为**（脚本 I/O、退出码、notes 管道、未实现 REQ 跳过），其余约 30 条是"某文档含某词"（如 `req0046-two-paths` 查 `lifecycle.md` 含「实现路」「评审路」），约 20 条是 `skill-validate-ok`。

**"某文档含某词"= 自洽项换了件 check 的外衣**——一改措辞就红。这正是"反复发现、反复修"的第二个来源。新模型下：**不变量只收行为 / 接口**，文档措辞检查应归**清理清单**，不占不变量集。

### 发现 3：一条标准常常**混着**不变量与 episode，要"切"而不是"贴标签"

例（`REQ-0010`）：

> `description` ≤ 1024 字符（2026-09-17 实测 166；`REQ-0021` 加「逼问」域限定后由 150 增至 166）。

切成两条：

- **不变量**：`description` ≤ 1024 字符 → 晋升为 check。
- **episode**：实测 166 / 150→166 → 冻结在工单里。

例（`REQ-0006`）：

> `lifecycle.md` 阶段 0 引用 `grilling.md`，不再重复其正文。

- **不变量**：阶段 0 引用 `grilling.md`。
- **episode**：「不再重复其正文」（相对改前而言）→ 冻结。

所以"二分"是**逐条拆句**，不是给整条打一个标。

## 3. 试跑后的复审范围

| | 现在 | 新模型 |
| --- | --- | --- |
| 每轮 Spec 轴扫 | 296 条（含 49 份历史 REQ 的全部散文） | **不变量集**（行为 / 接口，估 ~60–120 条） |
| 历史 REQ 散文 | 每轮重读 → 反复漂移 | **冻结，不读** |
| 文档措辞检查 | 混在 check 里，每轮重跑 | 清理清单，不阻断 |
| meta（查别的 REQ） | 混在 check 里，每轮重跑 | 冻结 |

**要点：收敛靠的不是"条数变少"，而是"每轮重查的东西不再随历史增长、不再因改措辞而红"。**

## 5. 试跑暴露的、需要回到设计层的问题

1. **不变量集必须先限定"只收行为/接口"**，否则 150 条散文晋升后会变成 150 条新的措辞检查，漂移问题只是搬家。
2. **`skill-validate-ok` 重复 20 次**：应合并为 1 条全局不变量（每次只跑一次）。
3. **episode 的显式标记**：初筛靠关键词，误判难免；建议落 `（episode）` 标记供人复核。
4. **谁来切 227 条**：一次性大扫，还是"碰到哪份标哪份"（增量）？

## 7. 子串 check 假警报验证（隔离副本实测，2026-09-18）

在临时副本上跑（不动真仓库）。**可复现**：`python docs/shy-skill-suite/design/pilot-0046.py .` → 退出码 0（仓库已迁移后，脚本退化为回归守卫）。

| 步骤 | 结果 |
| --- | --- |
| 基线 `run_checks` | 52 通过 / 0 失败 |
| **A. 无害措辞打磨**（`lifecycle.md`：不自动再审→不再自动复审、实现路→实现路径…） | `req0046-user-triggered` **FAIL**、`req0046-triage` **FAIL**（**假警报**）；`validate_skill` 仍 **ok**（证明改动无害） |
| ↳ 附带发现 | `req0046-two-paths` 仍 **PASS**（「实现路径」含子串「实现路」）→ 子串检查**两个方向都不可靠**（同义改写会假警报、子串巧合会漏报） |
| **B. 注入真回归**（`run_checks` 跳过逻辑退回 REQ-0046 修复前） | `req0046-unimplemented-skipped` **FAIL**（rc=1）→ **行为不变量抓到真回归** |

**结论（限定，勿过度声称）**：本实验验证的是**旧问题**——子串 check 会在无害措辞上假警报。它**顺带**支持方案的一个点：同一实验中**行为不变量**（`req0046-unimplemented-skipped`）不受措辞影响、且抓到真回归，即"行为不变量比子串 check 假警报率低"。

**但它没有验证方案的核心承诺（"把散文晋升为不变量后，不变量集能收敛"）。** 那需要在 1–2 份 REQ 上真正做晋升后再测，见设计说明 §9「未验证」。

## 8. 由此得到的精化（已回写设计说明 §4.2）

**不变量 ≠ 可执行 check。** 对本技能这种**文档驱动**的技能，文档里的**规则**确实是行为不变量（该保留）；但**子串检查不是测它的正确工具**——它对同义改写假警报、对子串巧合漏报。所以：

- **规则** → 语义不变量（人 / agent 判，值得时上行为 eval）；
- **子串 check** → 退休（它只是弱代理）。

这条修正很关键：否则"把措辞检查全归清理清单"会连**真规则**一起丢掉。

（v4 进一步把"判不准"单列为**未定 / 迁移债**——不设默认值，见设计说明 §4.2。）
