# REQ-0001 索引结构改造（根目录「总目录 + 疑问」，分类纯笔记）

## 问题与目标

现在索引是**每分类一份** `00-分类索引.md`（笔记导航表 + 已收录疑问）。问题：

- **没有全库目录**：总览要逐类翻；判"新建 / 合并"只能靠 `search-notes` 关键词检索，**旧笔记用词不同就漏合并 → 重复建笔记**（技能自身也承认这个召回缺口）。
- **索引分散**：N 个分类 = N 份索引，各处维护。

目标：把导航**收敛到根目录**，让"判 合并 / 新建 / 分类"一次读取就够，结构更清晰。

## 触发与分支

技能内部结构改动，用户不直接触发；影响「保存笔记」全流程（Step 0 / 2 / 3 / 6）与「检索已有笔记」「健康检查」。存量笔记库需一次性迁移（见 §备注）。

## 行为与步骤

新结构：

```
AI笔记/
├── 总目录.md      # 全库目录：分类 → 笔记 + 一句话摘要
├── 疑问.md        # 已收录疑问：疑问 → 笔记链接（可并列多篇）
├── 分类A/         # 纯笔记文件夹
└── 分类B/
```

- 根目录只维护两份索引：`总目录.md`（导航）与 `疑问.md`（疑问），且**两份分开**——用途与读取时机不同（导航判合并、疑问查重），合在一起每次都会多读另一半。
- 分类目录 = **纯笔记文件夹**，不再放 `00-分类索引.md`。
- 判"新建 / 合并 / 分类"（Step 2）：读 `总目录.md`（一次拿到全库标题 + 摘要）→ 挑候选 → 需要时读候选笔记全文。
- 写入后（Step 6）：更新 `总目录.md` 对应行；有新疑问则更新 `疑问.md`。
- **两级读取**（规模大时）：先拿"全部分类 + 标题"（很轻），再读候选分类的摘要 / 正文；`总目录.md` / `疑问.md` 支持**按分类切片返回**（脚本读全文、只把切片交给 agent）。

## 脚本与资源

- `list-structure`：改为返回分类 + 每篇**标题 + 一句话摘要**（供 Step 2 一次读取）；或新增 `read-toc`。
- 原 `list-index` / `append-index-entry` / `append-index-question` / `list-questions`：改为读写根目录的 `总目录.md` / `疑问.md`，并支持按分类切片。
- `lint-notes`：索引对齐检查改为对照根目录索引。
- `assets/分类索引模板.md`：废弃或改为根索引模板。
- `references/*-best-practices.md`、`SKILL.md`：同步索引结构说明。

## 降级与边界

- 根目录索引是**热点文件**：每次保存都要改，随库增长变大。技能目标规模为几十篇，可接受；几百篇再依赖"按分类切片"。
- 判合并**仍需读候选笔记全文**（摘要只是第一层过滤）。
- 存量库需迁移（旧分类索引 → 根索引）。

## 验收标准

- [ ] 新库写入后，根目录出现 `总目录.md` 与 `疑问.md`，分类目录下**没有** `00-分类索引.md`。
- [ ] `总目录.md` 列出全部分类与每篇笔记的标题 + 一句话摘要。
- [ ] 判"新建 / 合并"时读 `总目录.md` 即可覆盖全库（含跨分类）。
- [ ] 新增疑问更新 `疑问.md`；同一疑问合并链接、不重复成条。
- [ ] 支持按分类切片返回索引内容（脚本读全文、返回切片）。
- [ ] 存量库可一次性迁移，迁移后结构一致。

## 范围外

- 不改笔记正文格式与写作规则。
- 不做跨用户 / 多库同步。
- 不引入数据库或向量检索。
