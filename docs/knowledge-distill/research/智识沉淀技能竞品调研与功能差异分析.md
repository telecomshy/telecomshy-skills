# 智识沉淀技能竞品调研与功能差异分析

> 调研对象：`skills/knowledge-distill`（智识沉淀）技能
> 调研日期：2026-09-14
> 调研方法：**仅采用一手来源**（产品官方文档 / 官方帮助中心、项目 README 与源码仓库、官方 API 文档）。二手博客与清单类文章不作为事实依据；每条事实尽量回链到拥有该事实的一手页面。对无法从一手来源确认的行为，统一标注「未能从一手来源确认」，不做推测性断言。
> 说明：本报告不修改技能本体，仅新增本文件。

## 一、概述与调研范围

### 1.1 智识沉淀是什么（对照基线）

智识沉淀把一段 AI 对话蒸馏为**可长期复用**的知识库笔记，运行在 TeleAgent（Claude Code 式 Agent）平台。核心特征（来源：[`skills/knowledge-distill/SKILL.md`](../skills/knowledge-distill/SKILL.md)、[`references/design-boundaries.md`](../skills/knowledge-distill/references/design-boundaries.md)）：

- **产物**：独立的 `AI笔记` 根目录，一级子目录即分类，每分类维护 `00-分类索引.md`（笔记导航表 + 已收录疑问）。
- **格式**：默认 Obsidian（wikilink、callout、frontmatter），兼容普通 Markdown。
- **拆分/合并**：长对话按主题拆分为多篇；合并已有笔记分「追加（append-only）」与「改写优化（rewrite）」两种方式，默认建议追加。
- **链接**：Obsidian 只写单向双链 `[[笔记名]]`，反向链接交给 Obsidian 原生 Backlinks / Graph view；普通 Markdown 手工补反链。
- **防幻觉**：区分事实与推断（`(推断)`）、无法核实标 `(待核实)`、易变事实加日期；外部高价值/易失效事实「只核验、不沉淀」。
- **检索**：确定性脚本 `scripts/skill_tools.py` 做关键词/正则检索（`search-notes`），无向量/语义检索。
- **维护**：健康检查（断链/索引漂移/孤立笔记等）、MOC（内容地图）、事务化写入（备份 + 原子替换）。

### 1.2 明确的设计边界（本次评估的「护栏」）

来自 [`references/design-boundaries.md`](../skills/knowledge-distill/references/design-boundaries.md)：

| 边界 | 状态 |
| ---- | ---- |
| 向量 / 语义检索 | 明确不做（5–10 万 token 规模下关键词+读取更可靠、可解释） |
| 跨 Agent 平台兼容 | 明确不做（定位 TeleAgent 单平台） |
| 外部资料 / 网页接入沉淀 | 明确不做（只核验外部事实，不整篇摘录） |
| 置信度数值评分 | 明确不做（用 `(推断)`/`(待核实)` 定性标注） |
| 来源哈希追踪 | 明确不做（个人库追溯价值低） |
| 来源/置信度结构化字段 | 明确不做（与 `created`/`source` 及定性标注重复） |
| 自动 hooks / 定时任务 | 明确不做（属平台层能力） |
| 笔记文风偏好写入长期记忆 | 明确不做（文风随内容与当次指令定） |
| 疑问的语义判重自动化 | 明确不做（脚本做不准，由 LLM 比对） |
| 操作日志 `log.md` | **暂缓**（约 30 篇笔记后再做） |
| 修正全库清扫 | **暂缓**（同一事实被 3 篇以上复述时再做） |
| `search-notes` 结果排序 | **暂缓**（约 50 篇笔记后再做） |
| `stale_index` 改用内容依据 | **暂缓**（mtime 频繁误报时再做） |

### 1.3 调研范围（竞品分类）

本次覆盖四类，并补充了若干一手来源发现的直接同类：

1. **AI 对话→笔记 / 第二大脑**：Notion AI（含 AI Meeting Notes）、Mem、Tana（agentic meeting platform）与 Tana Outliner、Reflect、Khoj、Rewind（现状说明）、Logseq（知识库底座）。
2. **Obsidian / Logseq AI 插件**：Copilot for Obsidian、Smart Connections。
3. **Agent 记忆能力与技能**：Claude 记忆（CLAUDE.md + auto memory）、ChatGPT 记忆、MCP Knowledge Graph Memory Server、Claude Code Skills（Agent Skills 标准）。
4. **开源「对话→Markdown 知识库」蒸馏项目**：Basic Memory、AnticLaw、Chat2KB、claude-mem。

> 备注：任务示例中的 **Mem / Tana / Reflect / Rewind** 均已核验其当前一手页面；其中 **Rewind** 已发生产品转型，见 §2.1.6。示例中的 **Obsidian Copilot / Smart Connections / Logseq / Khoj** 均按官方 README/文档核验。

## 二、竞品清单

> 每个竞品按「定位 / 知识组织 / 链接·图谱 / 溯源与防幻觉 / 增量合并 / 检索方式 / 来源」记录。**未能从一手来源确认**的项如实标注。

### 2.1 AI 对话→笔记 / 第二大脑

#### 2.1.1 Notion AI（含 AI Meeting Notes）

- **定位**：内置于 Notion 工作区的 AI 助手 + Notion Agent（可创建/编辑页面、数据库）；AI Meeting Notes 转录会议并生成摘要。[^notion-ai]
- **知识组织**：页面/块/数据库；会议摘要可写入指定 database（`Default meetings database`）。[^notion-ai][^notion-meeting]
- **链接·图谱**：Notion AI 一手文档未描述自动双链或图视图；**未能从一手来源确认**其自动链接/图谱能力。[^notion-ai]
- **溯源与防幻觉**：AI Meeting Notes 摘要提供 **transcript 引用（citations）**，hover 看被引用的 transcript 片段、click 跳转到对应行；transcript 与摘要一并保留。[^notion-meeting]
- **增量合并**：Notion Agent 可创建与编辑页面/数据库（来源同一文档）；是否存在「自动去重并合并进已有笔记」**未能从一手来源确认**。[^notion-ai]
- **检索方式**：Enterprise Search 跨工作区页面 + 连接器（Slack、Google Drive 等）+ web；Research Mode 做深度检索与报告。[^notion-ai]
- **来源**：<https://www.notion.com/help/notion-ai-faqs>、<https://www.notion.com/help/ai-meeting-notes>

#### 2.1.2 Mem

- **定位**：AI Thought Partner，捕获想法/会议/研究并「在需要时带回」。[^mem-home]
- **知识组织**：Notes + Collections（一条笔记可属多个 collection，支持 Auto-organize 自动归档），无文件夹层级。[^mem-collections]
- **链接·图谱**：**未能从一手来源确认**显式双链/图谱；有 **Heads Up** 在工作时浮现相关笔记与 collection（「相关笔记」式关联）。[^mem-home][^mem-collections]
- **溯源与防幻觉**：**Clean Up** 以「蓝色=新增/改进、红色删除线=移除」的 diff 呈现建议，接受前可逐条审阅；支持版本历史与 undo。无 `(推断)`/`(待核实)` 类事实性标注。[^mem-cleanup][^mem-chat]
- **增量合并**：Mem Chat 会「智能创建或**更新**笔记，并用相关细节增强它」；可把新内容并入已有会议笔记的 agenda，并在版本历史中显示 diff（明确为「改写式合并」）。[^mem-chat]
- **检索方式**：三层——typeahead（标题匹配）→ full results（关键词 + 过滤）→ **Deep Search**（AI 语义匹配，可开关）。[^mem-search]
- **来源**：<https://help.mem.ai/> 及 /features/chat、/features/search、/features/collections、/features/clean-up

#### 2.1.3 Tana（agentic meeting platform）与 Tana Outliner

> **重要澄清**：Tana 官方明确说明，2020–2024 年名为「Tana」的 PKM outliner（Supertags/nodes/daily notes）已更名为 **Tana Outliner**，现址 <https://outliner.tana.inc>；当前 <https://tana.inc> 是**另一个产品**——agentic meeting platform。[^tana]

- **定位（Tana）**：原生视频会议 + 会中实时干活的 AI Agent + 持久化 **context graph**。[^tana]
- **知识组织**：context graph（协作知识库）+ semantic layer/types/fields；跨会议自动合并同一人/公司/决策/主题为单一记录（merge proposal，用户可接受/拒绝/手动触发）。[^tana]
- **链接·图谱**：graph 会链接相似节点并在相关时浮现；docs 支持 backlinks。[^tana]
- **溯源与防幻觉**：**AI 的每次变更都是 proposal**，带 diff，审阅后才 apply；支持 create/update/delete 三类提案、版本历史；官方把「可编辑/删除而非只追加」作为防止 append-only 系统「AI-slop」的机制。[^tana][^tana-proposals]
- **增量合并**：**最强项**——AI 可 edit/delete 已有内容，会议/聊天后给出**跨 graph 的 merge proposal**（显示 diff 与更新位置），用户 approve/reject。[^tana]
- **检索方式**：Search 按文本匹配，且可把一句话转成 filters；AI chat 可读、搜索、创建、更新、删除内容。[^tana]
- **来源**：<https://tana.inc/>（其文档为单页聚合，含 /learn/features/proposals、/learn/features/chat 等章节）

#### 2.1.4 Reflect

- **定位**：网络化笔记 + AI 助手（基于 OpenAI GPT-4 / Whisper）。[^reflect]
- **知识组织**：notes + backlinks + graph（「Mirror the way your mind works by associating notes through backlinks」）。[^reflect]
- **链接·图谱**：**backlinks 为核心**，构建 ideas graph。[^reflect]
- **溯源与防幻觉**：**未能从一手来源确认**其出处标注/防幻觉机制。
- **增量合并**：AI 可转写语音、生成大纲、抽取要点、修语法、保存自定义 prompt；是否有「合并进已有笔记」**未能从一手来源确认**。[^reflect]
- **检索方式**：官方称「Frictionless search … recall and index past notes and ideas」，未描述底层机制。[^reflect]
- **来源**：<https://reflect.app/>

#### 2.1.5 Khoj

- **定位**：个人 AI 第二大脑；对本地/在线文档做搜索与聊天，跨 Web/Obsidian/Emacs/Desktop/WhatsApp。[^khoj-readme]
- **知识组织**：**索引**已有文档（Markdown/Org/PDF/Word/Notion 等），本身**不生成/写回笔记**（检索型）。[^khoj-all]
- **链接·图谱**：**未能从一手来源确认**其图谱能力。
- **溯源与防幻觉**：Online Search 会「总是展示所用在线引用」；语义检索有 bi-encoder confidence threshold（内部阈值）。[^khoj-online][^khoj-search]
- **增量合并**：**不适用**（只读索引，无写回蒸馏笔记的一手描述）。[^khoj-all]
- **检索方式**：**bi-encoder 向量嵌入 + cross-encoder 重排**；增量索引、search-as-you-type。[^khoj-search]
- **来源**：<https://github.com/khoj-ai/khoj>、<https://docs.khoj.dev/features/search>、/features/all-features、/features/automations

#### 2.1.6 Rewind（现状说明）

- **现状**：原 Rewind（录屏/会议记忆类产品）对应的域名 <https://www.rewind.ai/> 现为一个 **AI 工具聚合站**（「Every AI Tool, Free to Start」，400+ 工具/模型），并设有「What Happened to Rewind AI」页面。[^rewind]
- **结论**：**不再作为智识沉淀的同类竞品**；原产品线去向未在本报告一手核验范围内（**未能从一手来源确认**其后继产品与知识组织方式）。[^rewind]
- **来源**：<https://www.rewind.ai/>

#### 2.1.7 Logseq（知识库底座）

- **定位**：隐私优先、开源的知识管理与协作平台，支持 Markdown / Org-mode；正在推进 DB version（DB graphs、RTC 实时协作，beta/alpha）。[^logseq]
- **知识组织**：outliner（blocks）；DB 版本引入 DB graphs。[^logseq]
- **链接·图谱**：官方定位为知识管理平台，图谱/双链为其文档核心能力（详见 <https://docs.logseq.com/>）。[^logseq]
- **溯源/增量合并/检索**：**无内建对话蒸馏能力**；相关 AI 能力主要来自插件生态（未逐一核验）。[^logseq]
- **来源**：<https://github.com/logseq/logseq>、<https://docs.logseq.com/>

### 2.2 Obsidian / Logseq AI 插件

#### 2.2.1 Copilot for Obsidian

- **定位**：把 opencode / Claude Code / Codex 带进 Obsidian 的 **Agent**（V4），面向研究、写作与知识工作。[^copilot-readme]
- **知识组织**：以你的 vault 为工作目录；Agent 可创建 Obsidian 文件；**Projects** 为持续工作提供独立指令、可复用上下文与聊天历史。[^copilot-agent]
- **链接·图谱**：由 vault/Obsidian 原生提供；`[[Note title]]` 可作上下文提及。[^copilot-agent]
- **溯源与防幻觉**：以 **permissioned changes** 与 **Plan**（先出只读计划）控制改动；官方明确「vault 是工作目录、不是安全沙箱」。无出处标注机制。[^copilot-agent]
- **增量合并**：Agent 直接编辑文件；**未能从一手来源确认**内建去重/合并策略。
- **检索方式**：README 提到 **local Miyo search**；未描述语义/关键词细节。[^copilot-readme]
- **来源**：<https://github.com/logancyang/obsidian-copilot>、`docs/agent-mode-and-tools.md`

#### 2.2.2 Smart Connections

- **定位**：Obsidian 插件，用**本地 embeddings** 找语义相关笔记（「Save time linking, tagging, and organizing」）。[^sc]
- **知识组织**：**不组织/不改写**笔记，只发现连接；可把结果拖入笔记以创建链接。[^sc]
- **链接·图谱**：通过建议 + 拖拽创建链接；**不自动写入双链**。[^sc]
- **溯源与防幻觉**：无（本质是相似度）。
- **增量合并**：**不适用**。
- **检索方式**：本地 embedding 语义相似（Connections view 带 result score）+ Lookup 语义搜索；官方明确语义搜索「与纯文本搜索不同，含精确查询词的笔记可能不出现」。[^sc]
- **来源**：<https://github.com/brianpetro/obsidian-smart-connections>

### 2.3 Agent 记忆能力与技能

#### 2.3.1 Claude 记忆（CLAUDE.md + auto memory）

- **定位**：Claude Code 的跨会话记忆双机制：**CLAUDE.md**（用户写的指令）+ **auto memory**（Claude 自己写的学习笔记）。[^claude-memory]
- **知识组织**：每项目一个目录 `~/.claude/projects/<project>/memory/`，含 **`MEMORY.md` 索引** + 每主题一个文件；文件 frontmatter 记录 `type`（user/feedback/project/reference）与 `modified` 时间戳。[^claude-memory]
- **链接·图谱**：无显式双链；`MEMORY.md` 作为索引指向主题文件。[^claude-memory]
- **溯源与防幻觉**：`modified` ISO 8601 时间戳显示事实新旧；无 `(推断)`/`(待核实)` 类标注。[^claude-memory]
- **增量合并**：Claude 会把细节移入主题文件、**合并或删除过时条目**；`MEMORY.md` 有 **200 行 / 25KB** 读取上限，超限会被要求重写索引。[^claude-memory]
- **检索方式**：启动加载 `MEMORY.md` 前 200 行/25KB；主题文件**按需读取**（无向量）。[^claude-memory]
- **来源**：<https://docs.claude.com/en/docs/claude-code/memory>

#### 2.3.2 ChatGPT 记忆

- **定位**：跨聊天的个性化记忆（memory summary + legacy saved memories）。[^chatgpt-mem]
- **知识组织**：**memory summary**（对过去聊天上下文的持续合成）+ 旧版 saved memories；非文件形态。[^chatgpt-mem]
- **链接·图谱**：无。[^chatgpt-mem]
- **溯源与防幻觉**：**Memories in sources**——回复下方书图标展示所用来源（自定义指令/历史聊天/文件/记忆），点开解释「为何使用该记忆」，可纠正。[^chatgpt-mem]
- **增量合并**：自动更新/合并/删除记忆；官方明确新系统要解决旧系统的 **stale 与互相矛盾**问题（举例「在跑马拉松」与「扭伤脚踝」）。[^chatgpt-mem]
- **检索方式**：由模型在生成时隐式使用；**无显式检索接口**。[^chatgpt-mem]
- **来源**：<https://help.openai.com/en/articles/8590148-memory-faq>

#### 2.3.3 MCP Knowledge Graph Memory Server

- **定位**：基于本地知识图谱的持久记忆，让 Claude 跨对话记住用户信息。[^mcp-memory]
- **知识组织**：知识图谱 = **Entities**（name/entityType/observations）+ **Relations**（from/to/relationType），持久化为 JSONL。[^mcp-memory]
- **链接·图谱**：relations 即图谱结构。[^mcp-memory]
- **溯源与防幻觉**：无。
- **增量合并**：`add_observations` 追加、`delete_*` 删除；`create_entities` **忽略同名实体**；`create_relations` **跳过重复关系**；删除实体级联删关系。[^mcp-memory]
- **检索方式**：`search_nodes`（跨实体名/类型/observation 文本）、`open_nodes`、`read_graph`。[^mcp-memory]
- **来源**：<https://github.com/modelcontextprotocol/servers/tree/main/src/memory>（README 原文）

#### 2.3.4 Claude Code Skills（Agent Skills 标准）

- **定位**：用 `SKILL.md` 封装可复用指令/流程，按需加载（progressive disclosure），支持 `scripts/`、`references/` 等支撑文件；遵循 [Agent Skills](https://agentskills.io) 开放标准。[^claude-skills]
- **知识组织 / 链接 / 溯源 / 合并 / 检索**：不适用——它是「能力封装机制」，不是知识库。
- **来源**：<https://docs.claude.com/en/docs/claude-code/skills>

### 2.4 开源「对话→Markdown 知识库」蒸馏项目

#### 2.4.1 Basic Memory

- **定位**：本地优先的 Markdown 知识库，让人与 AI 读写同一批文件，MCP-native。[^bm]
- **知识组织**：**每个文件 = 一个 Entity**，含 `Observations`（`[category]` 事实）与 `Relations`（wikilink）；frontmatter（title/type/permalink/tags）；本地 SQLite 索引。[^bm]
- **链接·图谱**：`[[Target]]` + 关系类型构成**可遍历图**；`build_context` 导航 `memory://` URL。[^bm]
- **溯源与防幻觉**：**未能从一手来源确认**显式防幻觉/出处标注。
- **增量合并**：`write_note` / `edit_note` / `move_note` / `delete_note`；人改与 AI 改**双向同步**；`basic-memory doctor` 做 file↔DB 一致性检查。[^bm]
- **检索方式**：**语义搜索（向量）**，可选 cross-encoder rerank 做更高质量的向量/混合结果；`search_notes`。[^bm]
- **导入**：`basic-memory import claude conversations`、`import chatgpt`。[^bm]
- **来源**：<https://github.com/basicmachines-co/basic-memory>

#### 2.4.2 AnticLaw

- **定位**：LLM 对话的本地优先知识库（`aw` CLI），把导出的对话管理为 Markdown + YAML frontmatter。[^anticlaw]
- **知识组织**：`~/anticlaw/` 下 `_inbox` / `_archive` / 各 project 目录；每条对话一个 `.md`，frontmatter 含 `id/title/created/provider/model/tags/summary/status`。[^anticlaw]
- **链接·图谱**：**MAGMA 知识图谱**（temporal/entity/semantic/causal 四类边），自动实体抽取，`aw why` 做决策追溯、`aw timeline` 时间视图。[^anticlaw]
- **溯源与防幻觉**：导入时 **secret scrubbing**（清洗 API key/密码）、**duplicate detection**（重复导入检测）；frontmatter 记录 provider/model/created。[^anticlaw]
- **增量合并**：re-import 去重；`aw health` 检查 KB 完整性；3 区生命周期（active→archive→purge）与重要性衰减。[^anticlaw]
- **检索方式**：**5 层**——keyword（SQLite FTS5）/ BM25 / fuzzy（RapidFuzz）/ semantic（ChromaDB+Ollama）/ hybrid。[^anticlaw]
- **来源**：<https://github.com/Goga74/AnticLaw>（README 中 CI 徽章指向的 `izamiatin/anticlaw` 经核验已 404，故以实际可访问仓库为准）

#### 2.4.3 Chat2KB（最直接同类）

- **定位**：把聊天对话转成结构化知识库 Markdown 的**跨平台 skill / agent capability**（Codex / Claude / QoderWork / OpenClaw）。[^chat2kb]
- **知识组织**：KB 文件夹（可由环境变量配置）+ YAML frontmatter；每段对话生成**唯一 conversation ID**。[^chat2kb]
- **链接·图谱**：**未能从一手来源确认**。
- **溯源与防幻觉**：**未能从一手来源确认**防幻觉标记；unique ID 用于引用与更新。[^chat2kb]
- **增量合并**：官方明确「**Incremental Export**: 支持 full export 或只追加新内容（appending only new content）」——即**追加式**。[^chat2kb]
- **检索方式**：**未能从一手来源确认**（依赖宿主/文件系统）。
- **来源**：<https://github.com/extraterrest/chat2kb>

#### 2.4.4 claude-mem

- **定位**：Claude Code 插件，用 5 个生命周期钩子自动捕获会话记忆。[^cmem]
- **知识组织**：SQLite（sessions/observations/summaries）+ **Chroma 向量库**。[^cmem]
- **链接·图谱**：**未能从一手来源确认**。
- **溯源与防幻觉**：**未能从一手来源确认**。
- **增量合并**：自动捕获与写入（hook 驱动）。[^cmem]
- **检索方式**：hybrid semantic + keyword；MCP **3 层工作流**（`search` 索引 → `timeline` 时间线 → `get_observations` 取详情），以省 token。[^cmem]
- **来源**：<https://github.com/thedotmack/claude-mem>

### 2.5 其它相关

- **Tana 的 MCP server**：外部 AI 工具可读写 Tana 内容，**写入一律生成需审阅的 proposal**（与内置 AI 一致）。[^tana]
- **Tana 的 external meeting agent**：可监听 Zoom/Meet/Teams（官方称因数据精度较低而「不推荐」）。[^tana]
- **MCP memory 生态**：MCP Knowledge Graph Memory Server（§2.3.3）与 Basic Memory、AnticLaw 均以 MCP 暴露工具，是「Agent 记忆」与「Markdown 知识库」的交叉带。

## 四、智识沉淀的差异化优势与短板

### 4.1 差异化优势（有竞品对照支撑）

1. **溯源与防幻觉规则最细**：区分事实/推断（`(推断)`）、`(待核实)`、易变事实加日期、外部事实「只核验不沉淀」、冲突显式标注不静默覆盖。竞品中仅 Notion（transcript 引用）、Tana（proposal diff）、ChatGPT（sources）、Khoj（引用）触及「溯源」，但**没有一家对「事实 vs 推断」做显式标注**。[^notion-meeting][^tana][^chatgpt-mem][^khoj-online]
2. **合并语义最完整**：明确区分「追加（保守，不动旧内容）」与「改写优化（可就地改写，保留旧有独有信息，且不消解结论冲突）」，并要求改写前给变更摘要、冲突需用户确认。竞品多为「单一路径」：Chat2KB 只追加；Mem/Tana/Basic Memory 走「可改写」但**未强调「追加 vs 改写」的选择权与冲突不静默覆盖**。[^chat2kb][^mem-chat][^tana][^bm]
3. **索引与健康检查的确定性治理**：每分类索引（笔记导航 + 已收录疑问）+ 八类 lint（断链/索引漂移/孤立/疑问孤儿/frontmatter/空章节/stale_index）。多数竞品要么无索引（Mem/Reflect），要么把一致性检查交给 CLI（Basic Memory `doctor`、AnticLaw `health`）。[^bm][^anticlaw]
4. **事务化写入 + 备份**：`write-note` 先备份（`~/.knowledge-distill-backups/`）、临时文件原子替换、内容相同返回 `unchanged`。竞品中版本历史是「事后回滚」，智识沉淀是「写前保护 + 写后可回滚」。[^bm]
5. **零重依赖**：仅一个确定性 Python 脚本，无向量库/数据库/服务；Khoj、Basic Memory、AnticLaw、claude-mem 均需 embeddings/向量库或本地 LLM（Ollama）。[^khoj-search][^bm][^anticlaw][^cmem]

### 4.2 短板（相对竞品）

1. **检索能力落后于第一梯队**：竞品普遍具备语义/向量或混合检索（Khoj、Smart Connections、Mem Deep Search、Basic Memory、AnticLaw、claude-mem）。智识沉淀只有关键词/正则且**结果不排序**（排序为暂缓项）。[^khoj-search][^sc][^mem-search][^bm][^anticlaw]
2. **无自动/后台维护**：claude-mem 用 5 个 hooks 自动捕获；Khoj/Tana 有 scheduled/automation；Claude auto memory 自动写入。智识沉淀刻意不做 hooks/定时（平台层边界）。[^cmem][^khoj-automation][^claude-memory]
3. **无「相关笔记」自动浮现**：Smart Connections（Connections view）、Mem（Heads Up）、Tana（graph 链接相似节点）能在写作时主动浮现相关笔记；智识沉淀需用户显式检索或生成 MOC。[^sc][^mem-home][^tana]
4. **无变更可视化 diff**：Mem Clean Up 的蓝/红 diff、Tana proposal 的 diff 让用户在落盘前直观审阅；智识沉淀仅要求「改写前给文字变更摘要」。[^mem-cleanup][^tana-proposals]
5. **单平台**：Chat2KB 覆盖 4 个平台，Basic Memory/AnticLaw 走 MCP 通用接入；智识沉淀限定 TeleAgent（刻意取舍）。[^chat2kb][^bm][^anticlaw]
6. **无外部资料沉淀**：所有竞品都能吃 web/文档（Notion Enterprise Search、Khoj 多源、Basic Memory imports、AnticLaw imports）；智识沉淀刻意只做「对话沉淀」。[^notion-ai][^khoj-all][^bm][^anticlaw]

### 4.3 对设计边界的再评估

| 边界 | 竞品现状 | 建议 |
| ---- | ---- | ---- |
| 无向量/语义检索 | 第一梯队几乎都上语义 | **维持**（规模 5–10 万 token 下，关键词+读取可解释、零依赖；但应在笔记量增长到触发条件时补「确定性排序」，缩小体验差距） |
| 单平台（TeleAgent） | Chat2KB/MCP 项目跨平台 | **维持**（跨平台兼容成本与收益不匹配；若未来接入 MCP，可另立边界讨论） |
| 无外部网页沉淀 | 竞品普遍多源 | **维持**（定位清晰；「只核验不沉淀」已是良好折中） |
| 无置信度数值 | 竞品亦极少用数值置信度 | **维持**（定性标注更不易误读） |
| 无 hooks/定时 | claude-mem/Khoj 有 | **维持**（属平台层；可用一句「检查笔记库」手动触发） |
| 无来源结构化字段 | Notion/ChatGPT 有 sources 面板 | **部分调整**：不引入 `confidence`，但可把现有 `source`/`created` 用得更一致（见建议 §5.4） |
| 无 per-note 风格记忆 | Notion 自定义 summary instructions、Mem Refine | **维持**（文风随内容与当次指令定更合理） |

## 五、下一步功能开发建议

> 每条含：建议、理由、与现有设计边界的关系（**边界内** / **需突破边界**）、优先级（P0 最高）。所有建议均以 §2 的一手来源为证据，不虚构竞品功能。

### P0-1. 合并落盘前的**可视化 diff 预览**（改写优化专用）

- **建议**：为「改写优化」合并新增一个「写前 diff 预览」步骤（脚本输出统一 diff 或新增/删除/替换高亮），用户确认后再 `write-note`；追加合并可选展示「将插入的位置」。
- **理由**：Mem Clean Up 以蓝=新增、红删除线=移除的 diff 让用户在**接受前**审阅；Tana 把每次 AI 变更做成带 diff 的 proposal 才 apply。智识沉淀目前只有文字版「变更摘要」，diff 能让「不静默覆盖旧结论」这一红线**可验证**。[^mem-cleanup][^tana-proposals]
- **边界关系**：**边界内**。不引入新检索/平台能力，只是把已有「先确认再合并」流程可视化；仍由脚本做确定性 diff、LLM 做语义判断。
- **优先级**：P0。

### P0-2. 确定性「疑似重复 / 可合并笔记」检测并入健康检查与 Step 2

- **建议**：在 `lint-notes` 增加一类（或在 Step 2 检索后提示）——按**标题、frontmatter 标签、关键词重叠度**给出「疑似同主题、建议合并」的候选对；只报告、不自动改。
- **理由**：AnticLaw 在 re-import 时做 **duplicate detection**；ChatGPT 记忆明确把「记忆互相矛盾/stale」当作要解决的问题；Tana 会对跨会议同一实体给出 merge proposal。智识沉淀的索引去重目前只覆盖「已收录疑问」，缺少「笔记之间」的重复发现。[^anticlaw][^chatgpt-mem][^tana]
- **边界关系**：**边界内**。用关键词/标签/标题的确定性重叠，不涉及「疑问的语义判重自动化」（仍列为明确不做）。
- **优先级**：P0。

### P1-3. `search-notes` 的**确定性排序**（已到触发条件的暂缓项）

- **建议**：在结果中加入确定性排序（如命中次数、标题命中优先、`updated` 时间新近度），并支持多关键词 AND/OR；保持关键词/正则实现。
- **理由**：Smart Connections、Mem Deep Search、Khoj 都以「排序/相关性」提升可用性；智识沉淀自身把「结果排序」列为「笔记 > 约 50 篇」的触发项，说明设计者已认可该方向。[^sc][^mem-search][^khoj-search][^design-boundaries]
- **边界关系**：**边界内**（触发条件已写明的暂缓项，非新边界）。**不**引入向量。
- **优先级**：P1。

### P1-4. 索引 / MOC 的**时效与一致性检查**扩展

- **建议**：`lint-notes` 增加「MOC 是否滞后（相关笔记变动后未刷新）」「同一疑问在多个分类索引重复登记」等确定性检查；沿用只读 + 用户确认后修复。
- **理由**：MOC 目前由 `gen-moc` 生成、需手动刷新，页面注明「请勿手工编辑（下次生成会覆盖）」，存在滞后风险；竞品把「一致性检查」作为维护入口（Basic Memory `doctor`、AnticLaw `health`）。[^bm][^anticlaw]
- **边界关系**：**边界内**（扩展已有确定性健康检查，不做语义判断）。
- **优先级**：P1。

### P1-5. 更明确的**来源锚点**（轻量，不引入哈希/置信度）

- **建议**：统一在笔记中写一行可追溯来源（如「来源：YYYY-MM-DD 对话」），并让 `source` frontmatter 字段的取值规范化（如 `dialogue`）；不改动 `created` 语义。
- **理由**：Notion 会议摘要提供 transcript 引用、ChatGPT 提供 sources 面板、Khoj 展示在线引用——「能回溯到来源」是行业共识；智识沉淀已有 `source` 字段与来源标注约定，只需更一致地落地。[^notion-meeting][^chatgpt-mem][^khoj-online]
- **边界关系**：**边界内**。**不**引入 `source_date`/`source_type`/`source_ref`/`confidence`（这些与现有字段重复，已被明确排除），**不**做来源哈希。
- **优先级**：P1。

### P2-6. 操作日志 `log.md`（按既定触发条件启动）

- **建议**：当笔记量接近约 30 篇时，新增 append-only 的操作日志（记录时间、动作、目标笔记、备份路径），供「想不起什么时候记的」时追溯。
- **理由**：这是 `design-boundaries.md` 已列明的**暂缓项与触发条件**，非新提案；claude-mem（自动记录会话）、Mem/Notion（版本历史）都体现「变更可追溯」的价值。[^design-boundaries][^cmem][^mem-chat]
- **边界关系**：**边界内**（暂缓项按其触发条件执行）。
- **优先级**：P2。

### P2-7. 导入「已导出的对话文本」作为沉淀来源

- **建议**：允许用户粘贴/导入一份对话导出文本（如 `.md`/`.txt`）作为 Step 0 的输入源，再走既有蒸馏流程。
- **理由**：Basic Memory 提供 `import claude conversations` / `import chatgpt`；AnticLaw 直接导入 Claude/ChatGPT 导出 ZIP；Chat2KB 支持多平台。智识沉淀当前只能处理「当前会话」。[^bm][^anticlaw][^chat2kb]
- **边界关系**：**需明确边界讨论**。它**不是**「外部网页/资料接入沉淀」（输入的仍是对话内容），也**不是**「跨平台适配」（不新增平台运行分支）；但会引入「非本会话内容」的信任/时效问题，建议先小范围验证并明确「导入内容同样受事实/推断规则约束」。
- **优先级**：P2。

### P3-8. 明确**不做**：hooks / 定时巡检、向量检索、跨平台

- **建议**：维持现状，不新增自动 hooks/定时任务、不引入向量检索、不扩平台。
- **理由**：hooks 属平台层（claude-mem 以 hook 自动捕获，Khoj/Tana 有 scheduled/automation）；向量检索在 5–10 万 token 规模下不如关键词可解释且零依赖；跨平台适配成本高。均与既有边界一致。[^cmem][^khoj-automation][^design-boundaries]
- **边界关系**：**维持边界**。
- **优先级**：P3（不作为）。
