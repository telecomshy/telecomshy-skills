# 智识沉淀 · 有道云笔记存储后端 实现方案

> 状态：**v1（写入闭环）已实现**；v2（检索增强 / lint / MOC）待做
> 分支：`feature/youdao-backend`
> 依据：`docs/智识沉淀技能接入飞书语雀Notion调研.md`、`docs/智识沉淀技能竞品调研与功能差异分析.md`，以及针对有道 CLI / 桌面端的一手核查（见 §14）。

---

## 1. 目标与结论

给 `knowledge-distill`（智识沉淀）增加 **「有道云笔记」作为可选的笔记存储**：用户首次配置时在 Obsidian / 普通 Markdown / 有道 之间选择；**选择有道时，笔记只存有道云端**，不再落本地笔记文件。

核心结论：

- 通过官方 **`youdaonote` CLI** 读写。该 CLI 的 backend 是**云端 MCP**（`https://open.mail.163.com/api/ynote/mcp/sse`），桌面端从同一云端账号同步，因此"用 CLI"不等于"用网页端"。
- 技能保留一个**很小的本地状态目录**：技能配置、临时草稿、滚动备份；**不保留笔记正文的长期副本**。
- 有道不具备的能力（双链、标签、版本回退、全文检索、反链）按 §5 降级处理。

## 2. 决策汇总（Q1–Q12）

| # | 决策点 | 结论 |
| - | ------ | ---- |
| Q1 | 存储模型 | 有道为**唯一存储**（选有道时不落本地笔记文件） |
| Q2 | 本地残留 | 允许一个**小状态目录**（配置、草稿、备份）；不存笔记正文长期副本 |
| Q3 | 接入方式 | 脚本调用官方 **`youdaonote` CLI**（不直连 MCP 工具） |
| Q4 | 内容模型 | 标准 Markdown；**无 frontmatter**；顶部一行元信息；callout 用 `:::` 高亮块；链接纯文本 |
| Q5 | 备份 / 回退 | 改写前**本地滚动备份**（保留最近 10 份）+ 桌面端「历史版本」兜底 |
| Q6 | 能力映射 | 见 §5 降级清单 |
| Q7 | 配置 / 状态 | `format: youdao`；API Key 归 CLI 管；映射**现查不缓存**；`note_root: AI笔记` |
| Q8 | 笔记间链接 | **纯文本**（无 URL、无双链） |
| Q9 | onboarding | **引导为主**；用 `youdaonote check --json` 检测就绪 |
| Q10 | 错误 / 限流 | 瞬时失败退避重试 3 次；认证/参数错误不重试；部分失败逐篇报告；保留草稿 |
| Q11 | 迁移 | 默认**不迁移** + 提供可选的一次性迁移命令 |
| Q12 | 首版范围 | v1 写入闭环；v2 只读与维护 |

## 3. 架构与数据流

```
用户 / LLM（SKILL.md 路由）
        │  python "<SKILL_DIR>/scripts/skill_tools.py" <子命令>
        ▼
skill_tools.py  ──(youdao backend)──►  youdaonote CLI  ──►  云端 MCP
        │                                      │                │
        │                                      │                ▼
        └── 本地状态：配置 / 草稿 / 备份        └────────  有道桌面端（同步后可见）
```

- **认证**：由 CLI 负责。Key 存 `~/.youdaonote.json`（或环境变量 `YOUDAONOTE_API_KEY`）；**技能不存 Key**。
- **配置**：`~/.knowledge-distill-config.json`，新增 `format: "youdao"`。
- **状态**：沿用 `~/.knowledge-distill-backups/`（滚动备份）与临时草稿文件。
- **概念映射**：分类 = 有道文件夹；索引 / MOC = 有道里的一篇 `.md` 笔记；笔记根目录名 = `AI笔记`。

## 4. CLI 集成细节

### 4.1 用 `call` 拿结构化 JSON（关键）

`list` / `search` / `read` **不支持 `--json`**（只输出文本行）。改用调试命令 `call`：

```bash
youdaonote call listNotes            --args '{"parentId":"0"}'
youdaonote call listNotes            --args '{"parentId":"<folderId>","lastId":"<cursor>"}'
youdaonote call searchNotes          --args '{"keyword":"...","startIndex":0}'
youdaonote call getNoteTextContent   --args '{"fileId":"..."}'          # 读正文
```

- `listNotes` / `searchNotes` → `entries[]`，形如 `{id, name, dir, parentId, version}`。
- `getNoteTextContent` → `{content, title, isRaw}`。
- `call` 的结果以 JSON 打印（对象即 `JSON.stringify(..., 2)`）。**脚本不再解析文本输出。**

### 4.2 写入

```bash
# 新建（Markdown，返回 fileId）
youdaonote call createAnyNote --args '{"title":"<标题>","type":"md","content":"<正文>","parentId":"<folderId>"}'
# 更新（仅 Markdown，全文覆盖）
youdaonote call updateMarkdownNote --args '{"fileId":"<id>","content":"<正文>","title":"<标题>"}'
# 新建分类文件夹
youdaonote call createDir --args '{"parentId":"0","dirName":"<分类名>"}'
# 其它：moveNote {fileId,targetParentId}、renameNote {fileId,newTitle}、deleteNote {fileId}
```

- **幂等写入**：先 `listNotes` 在该文件夹内按标题匹配 → 命中则 `updateMarkdownNote`，否则 `createAnyNote`（`createAnyNote` 是纯新建、不 upsert）。
- **覆盖语义**：`updateMarkdownNote` 为**全文覆盖**；因此合并场景 = 读原文 → 内存拼好 → 整体写回（写前先做本地备份）。

### 4.3 就绪检测与错误

- 就绪检测：`youdaonote check --json`（含 `cli-version` / `config-file` / `api-key` / `mcp-server` / `backend` / `mcp-connection` / `win-encoding`）。
- 退出码只有 `0` / `1`，错误信息在 stderr；**CLI 自身不做限流退避** → 由脚本实现（§8）。
- 工具名与参数形状来自官方 CLI 适配层（一手但非文档）；**端到端 JSON 形状需用真实 API Key 实测**（见 §13）。

## 5. 能力映射与降级清单

| 技能能力 | 有道映射 | 变化 |
| -------- | -------- | ---- |
| 分类 | 有道文件夹（`listNotes` / `createDir`） | ✅（但文件夹**不能改名/移动/删除**） |
| `AI笔记` 根 | 根文件夹 | ✅ |
| 索引 `00-分类索引.md` | 文件夹内一篇 `.md` 笔记 | ✅（读→改→`updateMarkdownNote`） |
| MOC | 根文件夹内一篇 `.md` | ✅ |
| `list-structure` | `listNotes` 逐层 | ✅（无时间戳） |
| `check-name` | `listNotes` 比对标题 | ✅ |
| `write-note` | 先查同名 → `update`，否则 `create` | ⚠️ 幂等靠先查；无原子替换（单次调用）；`create` 不 upsert |
| `search-notes` | `searchNotes`（仅标题） | ⚠️ **重度降级**：无片段/正则/排序；看正文需逐篇 `getNoteTextContent` |
| `lint-notes` | 部分 | ⚠️ `stale_index` 做不了（无时间戳）；`missing_frontmatter` 跳过；反链类做不了；`index_orphans`/`unindexed_notes`/`empty_sections`/`question_orphans` 可做 |
| `similar_notes` | 仅标题相似 | ⚠️ 标签没了 |
| `append-index-entry` / `-question` | 读索引→改→`update` | ✅ |
| 双链 / 反链 | — | ❌ 技能不写；桌面端**可手工加**（反链/图谱可用） |
| tags | 正文元信息行 | ⚠️ 无原生标签、无 API |
| 版本回退 | 本地备份 + 桌面端历史版本 | ⚠️ 无版本 API |

## 6. 内容模型（有道最佳实践）

写入内容为**标准 Markdown**（有道原生支持）：

- **无 frontmatter**（有道笔记无属性）。改为正文**顶部一行元信息**：
  `> 创建：YYYY-MM-DD ｜ 来源：对话 ｜ 标签：a、b`
- **callout 用高亮块**：`::: success` / `::: info` / `::: warning` / `::: danger`（对应 绿/蓝/黄/红；桌面端 7.1.8+ 渲染）。
- **链接用纯文本**：`相关笔记：标题A、标题B`（云端不支持 `[[wikilinks]]`，CLI 也给不出 URL）。
- 其余照标准 Markdown：标题层级、列表、代码块、引用、表格、待办 `- [ ]`、KaTeX 公式、Mermaid。
- 事实/推断标注（`(推断)` / `(待核实)`）、易变事实加日期等既有规则**不变**。
- 新增 `references/youdao-best-practices.md` 固化以上规则。

## 7. 配置与状态模型

- **字段**：`format` 增加第三个取值 `youdao`（内部按 markdown 方式渲染链接）。
  ```json
  { "format": "youdao", "note_root": "AI笔记" }
  ```
- **API Key**：只放 CLI 的 `~/.youdaonote.json`（或 `YOUDAONOTE_API_KEY`）；技能不读取、不存储。
- **映射**：`分类→文件夹ID`、`标题→fileId` **每次现查**（`listNotes`），不落缓存（避免桌面端改名/移动导致漂移）。
- **状态目录**：沿用 `~/.knowledge-distill-config.json` 与 `~/.knowledge-distill-backups/`。

## 8. 首次配置 onboarding（引导为主）

用户选「有道」后：

1. `youdaonote check --json` 检测 CLI 与认证。
2. **未就绪 → 引导**（不静默改全局配置）：
   - 安装 CLI（官方 tarball，涉及 PATH / 杀软）；
   - 去 `mopen.163.com` 申请 API Key（绑定手机账号，技能无法代申请）；
   - `youdaonote config set apiKey`（经用户同意可代为执行）。
3. 就绪 → 列根文件夹：`youdaonote call listNotes --args '{"parentId":"0"}'`，选一个或新建 `AI笔记`。
4. 写技能配置 `{ "format": "youdao", "note_root": "AI笔记" }`。

## 9. 迁移

- **默认不迁移**：切到有道时明确提示"已有本地笔记不会自动迁移"（沿用现有"只影响之后"语义）。
- **可选一次性命令** `migrate-to-youdao`：读本地 `AI笔记/<分类>/<笔记>.md` → 在有道建 `AI笔记` 文件夹 + 分类子文件夹 + 逐篇 `createAnyNote`，**逐篇报告**结果。由用户显式触发。

## 12. 不破坏现有功能的约束

- **新增而非替换**：有道是 `format` 的第三个取值；`obsidian` / `markdown` 的代码路径与行为**完全不变**。
- **回归**：`scripts/test_skill_tools.py` 必须全绿；新增 youdao 单测用 mock CLI。
- **配置向后兼容**：旧配置（无 `format: youdao`）行为不变；`format` 缺省仍为 `obsidian`。
- **边界条目**（追加到 `references/design-boundaries.md`）：

  > **云存储后端（有道）为可选、单账号、非镜像能力**：仅在 `format=youdao` 时启用；失败不阻断其它格式；不具备双链 / 标签 / 版本回退 / 全文检索 / 反链（降级说明见 SKILL.md 与 `youdao-best-practices.md`）。

- **发布前验收**：`main` 始终可发布；功能分支合入前跑全量测试，并用真实 API Key 手工跑通 v1 闭环。
