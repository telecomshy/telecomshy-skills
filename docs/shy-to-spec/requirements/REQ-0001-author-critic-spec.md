# REQ-0001 出规格前加三个盲评者对照 brief 挑漏，分歧点拿去问用户，不改上游 to-spec

## 问题与目标

`/to-spec` 由主代理独自综合对话成规格，漏需求是静默失败。子代理看不见对话，起草不能外包；但「独立眼睛」可以盲评形式补上。目标：主代理起草 + 3 个盲评子代理对照物化 brief 挑「缺失/加戏/矛盾」+ 主代理裁决合入（三档票数 3/3、2/3、1/3），**盲评者分歧点当作对话歧义**抛回用户澄清。触发场景：用户要「shy 出规格」、担心对话综合有遗漏、想借对拍暴露歧义。

## 触发与分支

「/shy-to-spec」「shy 出规格」→ 加载上游 `to-spec` 执行（探索、seam 确认、模板、发布），在「写规格」与「发布」之间插入盲评环。

## 行为与步骤

1. **物化 brief**（临时文件）：用户原话引述（含被否定的说法）、已定决策、已知约束、未决问题。**只收原料不下结论**。
2. **起草**：主代理独占上下文，照上游模板起草。
3. **盲评**（3 个子代理并行、互不可见、模型尽量不同）：输入 = brief + 草稿，输出 = 逐条「缺失 / 加戏 / 矛盾」（位置 + 引语）；不引入 brief 之外新事实。
4. **裁决合入**：共识（≥2/3）免检采信；孤证（1/3）对照 brief 与对话原文核对；分歧点（理解不一 / 拿不准）→ 问题清单问用户（可用 `to-questionnaire`），澄清后合入。
5. **发布**：照上游（issue tracker、`ready-for-agent`），brief 路径或要点附进可回溯处。
6. **快速模式**（用户明说要快）：2 个盲评者（票数 2/2、1/2）；降级同理按剩余人数出稿并标注。

## 脚本与资源

- 技能文件：`~/.agents/skills/shy-to-spec/SKILL.md`（薄封装，无 scripts/references）。
- brief 落 OS 临时目录，路径在交付说明中可追溯。

## 降级与边界

- 某盲评者失败 → 同模型重试一次；再失败按剩余人数出稿：2 个仍算对拍（标注），仅 1 个标注「未经盲评对拍」。
- 裁决拿不准 → 进分歧问题清单，不硬判、不静默删。
- 盲评者只读 brief + 草稿，不加新事实。
- 3 个是默认（与对拍同一甜点：三档票数）；快速模式 2 个并标注；4 个及以上不外推。
