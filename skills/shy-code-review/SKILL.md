# shy-code-review

`code-review` 的强化封装。**上游技能是流程事实源**：先用 Skill 工具加载 `code-review`（失败则读 `~/.agents/skills/code-review/SKILL.md`），按它的全流程执行（固定点、spec 来源、standards 来源 + 坏味基线、两轴分离），仅下面两步被本技能覆盖。上游怎么改，这里自动跟着走。

遍数默认 3（实测的质量甜点：3 跑并集召回约 9 成 5、第 4 跑边际≈0；三跑并行发出，延迟与 2 跑相当）。

## 成本闸门（第 0 步：委派任何子代理之前）

多跑对拍按子代理数量消耗 token（完整对拍 = 2 轴 × 3 跑 = **6 个子代理**，独立裁决 / 修复复核各再 +1）。**每次运行、委派前**先报规模并确认去向：

- 用户本轮已明确要求「多跑 / 对拍 / 要质量」→ 视为已确认，报一句规模即执行；
- 否则**默认走原生轻跑**（按上游 `code-review` 原样：2 个子代理），要用户主动选「对拍」才升级；
- 「快速模式」（2 跑对拍）作为中间档随选项给出。

## 覆盖点

### 第 4 步 · 三跑（原「每轴 1 个子代理」）

每个轴发 **3 个独立子代理**（运行 1–3），并行：

- 三跑的提示词**除运行标签外逐字相同**，互不可见；brief 沿用上游原文（standards 轴含坏味基线全文），末尾追加输出格式：逐条列 `| 位置(file:line 或 hunk) | 类别 | 硬违规/判断 | 描述 |`，无发现也要写「无发现」。
- 模型矩阵：**A、B、C 各一跑**（三个不同模型）。ID 查找顺序：仓库 `docs/agents/subagent-models.md`（`AGENTS.md` 指路）→ 用户级 `~/.config/opencode/shy-models.md`（`/shy-setup-models` 生成）→ 都没有则问用户或同模型凑满并标注。某个模型不可用 → 用可用模型**凑满 3 跑**（一模型 2 跑 + 另一模型 1 跑），报告标注实际矩阵；都不可用才同模型 3 跑。
- 解析模型 ID 先查模型目录（`opencode.models`，看不到想要的模型时加 `all: true`）；不猜 ID。
- 某跑失败：同模型重试一次；再失败按**剩余跑数**出报告——2 跑仍算对拍（票数按 `2/2`、`1/2`），仅剩 1 跑标注「未经对拍」。

**快速模式**（仅当用户明说要快 / 要省）：发 2 跑（A、B），票数按 `2/2`、`1/2`。裁决时若独报成真率高（说明还没打满），建议补第 3 跑，由用户决定。

### 第 5 步 · 轴内裁决（原「两轴原样呈现」）

**轴间仍然永不合并、不重排**；对拍与裁决只发生在轴内：

1. **归并**：同一问题的不同措辞合并为一条 finding，保留各跑出处与原始表述。
2. **共识免检**：≥2/3 跑报出的（含 `3/3`）直接采信。
3. **孤证必检**：仅 1 跑报出的逐条核对——
   - 代码事实对照**钉版本**看（`git show <fixed-point>:<path>`，工作树可能已前进）；
   - 「缺失」类（缺文档 / 缺测试）先回仓库现状核对：缺失物可能在 diff 之外早已存在；
   - 核不过 → 剔除，记一句依据。
4. **报告**：两轴分开（`## Standards` / `## Spec`，格式照上游），每条 finding 标**票数**（`3/3`、`2/3`、`1/3`）与**裁决**（采信 / 复核后采信 / 剔除+依据）。结尾照上游给每轴一行汇总，另加一行对拍统计：各跑各报几条、独报几条、剔除几条。

### 第 6 步 · 独立裁决与修复复核（可选的两道独立工序）

裁决与修复常落回主代理手里（实现者 = 裁决者 = 修复者即自审）。两类时机各补一道独立工序，**都只读、不改代码**：

- **独立裁决**（孤证裁决出自实现者 / 主代理之手时）：派 1 个独立裁决子代理，**模型与实现者、三个评审都不同**；只喂各跑**原始报告**与规格来源，**不喂主代理的裁决**（防锚定）；全量重裁并自行归并。与主代理裁决逐条对照，分歧摆开呈现、注明最终采用哪方及理由（实测：这道工序抓出过主代理「同规则不同尺度」的双标）。
- **修复复核**（修复批落地后）：派 1 个独立子代理只读复核 fix diff，逐 finding 判「正确修复 / 不完整 / 未修 / 不修是对的」，另扫修复是否引入新问题（重点核对被重构处的行为语义是否保持）。

产出并入报告或单独呈现；修不修仍由用户拍板。

## 完成判据

- 两轴各有报告，轴间未合并、未重排。
- 每条 finding 有票数与裁决结果；每条被剔除的有一句依据。
- 降级（某跑失败、快速模式、模型与约定不符）已在报告标注。

## 降级与边界

- 自审不算一跑：实现这段代码的 agent 产出的复核，只能标为自审，不能顶替独立运行。
- 换模型是运行失败时的显式决策（问用户或按仓库约定），失败本身不是换模型的许可。
- 3 跑是默认（质量甜点）；快速模式 2 跑并标注；4 跑及以上不外推（边际≈0、噪声涨）。
