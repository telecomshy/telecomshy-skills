# 写好一个技能

技能是**写给 agent 读**的指导手册。下面是"怎么写对"的 lever。复审（`reviewing-skills.md`）用**同一套 lever** 做检查——**定义以本文件为准**，复审只保留检查动作。

## 1. description：唯一的触发指针

- 说清**做什么 + 何时用**，用祈使句（"当……时使用本技能"），聚焦**用户意图**而非实现机制。
- **一分支一触发**：同一分支的同义说法合并，只留真正不同的分支。
- 对边界场景**宁可"pushy"**地列全（模型倾向漏触发）。
- 硬约束：`description` ≤ 1024 字符；`name` 与目录同名、小写字母 / 数字 / 连字符。

## 2. 调用方式

只有人手动调用、且没有别的技能要引用它 → **user-invoked**（不付常驻上下文）；否则才 **model-invoked**。选错是持续的上下文浪费。

落地：user-invoked 在 frontmatter 写 `disable-model-invocation: true`；需要参数提示时再写 `argument-hint: "<提示>"`。二者是**客户端扩展字段**（不在 `agentskills.io` 基础字段集内），`validate_skill.py` 已列入允许集。

**opencode 路线**：opencode 只认 `name`/`description` 等基础字段，**忽略 `disable-model-invocation`**——它的技能一律 model-invoked，user 侧快捷入口是**客户端 command**：`~/.config/opencode/commands/<name>.md`（body 是 prompt 模板，可用 `$ARGUMENTS`），调用即 `/<name>`。command **不在技能包内自动生效**，技能只能放模板 + 复制说明。要"必须人工触发"的动作，用 command，别靠 `disable-model-invocation`。

## 3. 信息层级与按需披露

- **步骤**（agent 按序做的事）留主文件；**只在部分分支才需要的参考**下放到 `references/`，并给**何时加载**的指针（"API 返回非 200 时读 `references/api-errors.md`"），不要笼统的"详见 references/"。
- 主文件目标 **< 500 行 / < 5k token**。
- 文件引用**相对技能根、保持一层深**。

## 4. co-location

一个概念的**定义、规则、例外**聚在同一标题下，不要散落多处。

## 5. leading word

反复出现的三词短语、用一句话指代一个概念的段落 → 收敛成一个**模型已认识**的词（`no-op`、`cache`、`gotcha`）。少 token，且给 agent 一个挂思考的钩子。

## 6. 否定句

用"不要做 X"会把 X 拉进上下文、反而更可得。**改成正面目标**（"写一行注释"而非"不要写多行注释"）。

## 7. 剪枝

- **单一事实源**：一个含义只写一处（需求文档 / `SKILL.md` / `references/` 之间不重复）。
- **cache**：别抄环境能查到的（`package.json` 脚本、`--help`、目录结构）——只留查不到的：不成文的约定、选择的原因、坑。
- **relevance / sediment**：逐段问"这行还相关吗"；陈旧层要删。
- **no-op**：模型默认就会做的（"要注意边界""保持简洁"）→ 删。判据是**模型默认行为**，不确定就删掉跑一次对比。

## 8. 步骤与完成判据

- 每个 step 有**可判定的完成判据**（done vs not-done）；模糊的（"理解到位"）会诱发**提前收工**。
- 判据的**强度**要够（"每个改动的模型都要交代" > "产出一份变更清单"）。
- 破坏性 / 批量操作：plan → validate → execute + `--dry-run` + 验证回路（做 → 校验 → 修 → 再校验）。

## 9. 校准：把控制力度对准脆弱度

- 顺序敏感、必须一致的 → **写死**（"按此序列执行，勿加 flag"）；多解、容错 → **解释 why**，让 agent 自己判断。多数技能是混合的，逐段校准。
- **给默认而非菜单**：多个方案并列会让 agent 反复试错；挑一个默认，其余一句带过。
- **教方法而非给答案**：可复用的 procedure 优于只对当前实例有效的具体答案（输出模板、格式约束这类"具体"是合理例外）。

## 10. 何时拆分

- **按序列**：后续步骤可见会诱发抢跑 → 优先收紧判据，仍不行再拆（拆分只在真正的上下文边界有效）。
- **按调用**：有**独立触发词**、或别的技能要引用 → 拆成独立技能；否则别拆（每多一个技能就多一份常驻 `description`）。
