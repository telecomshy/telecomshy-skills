# 套件词汇（glossary）

> 本技能自己造的词。**含义以本文件为准**；其余 `references/` 只补用法，不另立定义。
> 解释 / 报告用到这些词时，配一行白话（见 `reviewing-skills.md` Step 8）。被开发技能的领域词另放 `docs/<skill>/glossary.md`（见 `grilling.md`）。
> 格式：`术语` + 一行白话 + `_避免_`（不再使用的说法，防止含义漂移）。

**Gate**：每次改动都跑的确定性检查（`validate_skill` + `run_checks` + `selftest`），绿了就过、红了才说。
_避免_：门禁、自动检查

**Discovery**：低频、对抗式找新问题；只在真实失败 / 用户显式要求时触发。
_避免_：扫描、自动检查

**不变量**：以后每次都要成立、需反复回归的行为 / 接口标准；机器能判的写成 `check:`，不能机器判的以（行为）/（语义）每轮判。
_避免_：断言、测试、验收项

**episode**：一次性事实（旧值、实测数字、某份文档被改）；冻结，不再重查。
_避免_：快照、历史记录

**迁移债**：还没分类成 不变量 / episode 的验收标准数；目标趋零。
_避免_：未分类、遗留项

**frontier**：现在就能开工的 REQ（`status ∈ {ready, in-progress}` 且前置全部 `done`）。
_避免_：待办、队列、backlog

**台账**：`cleanup.md`；自洽 / 卫生问题的唯一归宿，不进 findings、不阻断。
_避免_：问题列表、issue 清单

**converged**：脚本机械算出的「无失败 + 无未注册 check + 债达标」；一个 REQ 都没扫到时判「不适用」、不算收敛；agent 不得手写。
_避免_：通过、完成、绿

**三轴**：复审的 行为 / 需求（Spec）/ 标准 三条轴；分开报告、不合并。
_避免_：维度、方面

**分拣**：用户对每条 finding 选 立即修 / 以后修 / 丢弃；逐条做，不批量。
_避免_：triage、处理、筛选

**评测（eval）**：独立、user-invoked 的取证路径（`/shy-eval`）；只产触发率 / with_skill vs baseline 的 delta，不改技能、不提修复建议。
_避免_：测试、跑分

**复审（review）**：找问题 + 提修复建议；证据**可选**——有指纹匹配的 eval 则引用，无则显式降级。
_避免_：检查、审计

**（静态）**：无匹配 eval 证据时，复审对行为轴（触发率 / delta）的降级标注——只凭静态阅读判断，未跑 eval。
_避免_：未验证、推测

**过期证据**：技能在 eval 之后已变更（指纹不匹配）的旧证据；不删、留旧目录供追溯，但不作本轮证据。
_避免_：旧数据、历史结果
