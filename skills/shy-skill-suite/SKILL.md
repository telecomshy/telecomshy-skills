# 技能开发套件

覆盖一个技能的**生命周期**：需求 → 生成 → 复审 → 迭代。两条分支各有规范文件，按用户意图进入对应分支。

## 分支路由

| 用户意图 | 进入 |
| --- | --- |
| 新建 / 修改技能，要落盘需求文档；"写需求""需求文档""这个改动要做什么" | [`references/writing-requirements.md`](references/writing-requirements.md) |
| AI 生成 / 改写技能后复审；"评估这个技能""检查技能""触发准不准""提改进意见""继续迭代" | [`references/reviewing-skills.md`](references/reviewing-skills.md) |

## 共用原则（两条分支都遵守）

- **单一事实源**：一个含义只在一处写；需求文档、`SKILL.md`、`references/` 之间不重复。
- **技能必须自包含**：技能文件（`SKILL.md` / `scripts/` / `references/` / `assets/`）只引用技能自身（相对技能根的路径），不引用仓库级 `docs/` 等外部路径——技能会被单独复制部署，外部引用就是悬空指针。
- **先删后加**：能删的不要改，能改的不要加。
- **证据优先**：没有真实执行轨迹或对照证据的判断，只能标"待验证"，不能当结论。

## 资源

- `references/writing-requirements.md` — 技能需求文档的用途、命名、结构、写作原则、状态词表与模板。
- `references/reviewing-skills.md` — 生成 / 改写技能后的复审流程、判据、改进意见写法与反模式。

## 范围外

不负责被开发技能的具体领域实现；只负责"如何写技能需求"与"如何复审技能"两件事的规范。
