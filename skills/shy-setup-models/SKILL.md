# shy-setup-models

给 shy 系列（`shy-code-review` / `shy-to-spec` / `shy-to-tickets` / `shy-improve-codebase-architecture`）配置子代理模型矩阵。**一次性环节**（先例：`setup-matt-pocock-skills`）；换机器 / 换凭据后重跑即可。

产物是**用户级矩阵文件** `~/.config/opencode/shy-models.md`（跟人走），也是各 `shy-*` 技能**唯一**的模型来源（不读仓库级文件）。文件缺失时由各 `shy-*` 先问用户（并建议跑本技能），问不出再同模型凑满并标注。

大目录**不浏览、只确认**：模型目录动辄几百条，交互设计是「插槽 + 推荐 + 确认」，用户看到的候选不超过 6 行。

## 步骤

1. **分片拉目录**（别把几百条灌进上下文）：`opencode.models` 先看 provider 分组与各家总数（看不到想要的加 `all: true`——默认列表会藏非最新代）→ 请用户挑 2–3 家 provider，或**直接报模型 ID 跳过全程**（逃生门）→ 按 `provider` 过滤逐家拉，只看文本模型。
2. **机器筛**：排除 TTS / 语音克隆 / Vision / 嵌入等非文本模型与旧版本变体；每 provider 只留最新一代。
3. **按插槽推荐**（每槽 1 推荐 + 至多 1 备选，合计 ≤ 6 行）：
   - **A**：快而便宜的文本模型——对拍的基线跑；
   - **B**：**不同 provider / 模型家族**——互查互补性的来源；
   - **C**：第三方再一族——三跑三档票数（`3/3`、`2/3`、`1/3`）需要三个独立视角；凑不齐三家时 C 复跑较便宜一侧，矩阵注明「2 模型凑 3 跑」。
4. **确认制**：呈现 ≤ 6 行让用户拍板（最省事的回答是「按推荐」）；用户可随时直接指定 ID 覆盖任一槽。**选型 why 一并问清或代拟后确认**——选择比理由活得久，why 必须落盘。
5. **连通性探测**：三个 ID 各发一句话 ping（「只回复两个字：通了」）；连不通换备选再探；仍不通则矩阵标注「不可用，降级凑满 3 跑 = X×2 + Y×1」。
6. **写矩阵** `~/.config/opencode/shy-models.md`（格式见下）。用写盘工具写（UTF-8 无 BOM），不经管道。

## 矩阵文件格式

```markdown
# shy 子代理模型矩阵（用户级，/shy-setup-models 生成）

| 槽 | model（providerID/modelID） | why |
| --- | --- | --- |
| A | … | 快/便宜的基线跑 |
| B | … | 不同家族，互查互补 |
| C | … | 第三方视角 |

探测：<日期> 三跑全通 / <槽> 不可用（降级：凑满 3 跑 = X×2 + Y×1）
```

## 完成判据

- 三个槽各有 `providerID/modelID` 与 why，用户确认过推荐（或直接指定了 ID）。
- 每个 ID 经探测；结果与降级说明写进矩阵。
- 矩阵文件落盘且格式如上。

## 降级与边界

- 查不到想要的模型：加 `all: true` 再查一次；查无则如实说——不猜 ID（ID 会漂移，用前必须过目录）。
- 只挑目录里**已可用**的模型；provider 与凭据归 OpenCode 自己管，本技能不改 `opencode.jsonc`。
- 用户级矩阵缺失时的兜底：先问用户（并建议跑本技能），问不出再同模型凑满并标注。
