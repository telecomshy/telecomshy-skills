# Obsidian 笔记最佳实践（智识沉淀专用）

本参考文件用于指导生成符合 Obsidian 规范的笔记。仅当保存格式为 Obsidian 时查阅。
核心资料来源见技能 `assets/` 目录（官方基础/高级语法、Callouts、Tags、Flavored Markdown）。

---

## 一、笔记 frontmatter（Properties）

每个 Obsidian 笔记以 YAML frontmatter 开头，用属性承载元数据。

**必填字段**：

| 字段 | 说明 |
| --- | --- |
| `tags` | YAML **列表**格式，至少包含分类名与主题关键词 |
| `created` | 创建日期，`YYYY-MM-DD` |
| `source` | 内容来源，如 `对话总结` |

**可选字段**：

| 字段 | 说明 |
| --- | --- |
| `aliases` | 别名，中文标题建议补充，便于检索与双链匹配 |
| `updated` | 仅合并更新既有笔记时写入 |

```yaml
---
tags:
  - 知识沉淀
  - 示例分类
created: 2026-09-09
source: 对话总结
---
```

- `tags` 在 YAML 中**必须写成列表**格式。
- 标签可嵌套，用 `/` 构成层级，如 `#层级/子类`。搜索 `tag:层级` 可同时命中子标签。
- 标签不能含空格；多词用 `#camelCase`、`#snake_case`、`#kebab-case` 等风格。
- 标签大小写不敏感。

## 二、双链（Wikilink）—— 形成知识图谱的核心

用双链 `[[笔记名]]` 关联其它笔记，支撑知识图谱（Graph view）。

- 内部链接两种写法：
  - Wikilink：`[[示例笔记标题]]`
  - Markdown 风格：`[示例笔记标题](示例笔记标题.md)`
  - Markdown 风格下标题含空格或特殊字符时，用 `<...>` 包裹或 `%20` 编码：
    `[显示文字](<含 空格的标题.md>)`、`[显示文字](含%20空格的标题.md)`。
- **推荐优先用 Wikilink** `[[笔记名]]`，Obsidian 原生支持。
- 链到指定标题：`[[笔记名#章节]]`；链到锚点块：`[[笔记名#^块id]]`。
- 链到**本篇内**的标题：`[[#章节标题]]`（省略笔记名，用于长笔记内部跳转，如目录）。
- 自定义链接显示文字：`[[笔记名|显示文字]]`。
- **块 ID 的定义**（必须定义，否则 `[[笔记名#^块id]]` 会指向不存在的锚点，且 `lint-notes` 只校验笔记是否存在、查不出块 ID 失效）：
  - 段落：在段落**末尾**加 `^块id`，如 `这段文字可以被引用。^my-block-id`。
  - 列表 / 引用：块 ID 单独写在块**之后**一行，如：
    ```markdown
    > 一段引用

    ^quote-id
    ```
  - 块 ID 只含字母、数字、连字符，全库内应唯一。
- **嵌入（`![[...]]`）——本技能不使用**：在链接前加 `!` 可把目标内容嵌入当前笔记（如 `![[图片.png]]`、`![[笔记名#章节]]`）。知识沉淀场景**刻意不用**，理由：
  - 嵌入会把内容复制进当前笔记，违反「单一源头、只链接不复述」原则——同一内容在多篇笔记各存一份，日后修正时容易漏改。
  - 表达关联用普通双链 `[[笔记名]]` 即可，内容留在原笔记，需要时点开查看。
  - 例外：确实要展示图片时可用 `![[图片.png|宽度]]`，图片不属于「会被修正的文本」。
- 相互关联：**只在本篇写单向双链**即可。Obsidian 会自动生成反向链接（Backlinks 面板、Graph view），**不需要**手工去其它笔记补反向链接——那既冗余，又会写到用户自己创建的笔记里。引用了某个概念，就在本篇链向目标笔记。

> **写作原则**：写完笔记后，检查文中提到的既有概念/笔记，能链则链；无法链到既有笔记时，至少保持内容自洽，待后续新建相关笔记时回补链接。反向链接交给 Obsidian 原生能力，不手工维护。

## 三、Callouts（醒目提示块）

用 `> [!类型] 标题` 创建提示框，适合标注注意事项、坑、要点，不打断正文。

```markdown
> [!warning] 踩坑注意
> **注意**：变更前必须备份，避免回滚失败。
```

常用类型：`note`、`tip`（提示）、`info`、`question`/`faq`（疑问）、`warning`/`caution`（警告）、`danger`/`error`、`success`/`done`、`example`、`quote`。

可折叠：类型后加 `+`（默认展开）或 `-`（默认折叠），如 `> [!faq]- 常见疑问`。

适用场景：
- 用 `> [!question]` 沉淀"用户疑问 + 解答"。
- 用 `> [!warning]` 标记易错点、坑。
- 用 `> [!tip]` 标注实用技巧，或承载对抽象概念的通俗解释、类比（如 `> [!tip] 通俗理解`）。

## 四、正文排版要点

- 标题层级最多六级，用 `#` 数量控制；按从大到小编号，保持一致层级（如 `#` 标题、`##` 小节）。
- **一级标题 `#` 固定用作笔记标题**（与文件名一致），正文章节从 `##` 开始，避免标题与文件名重复、Outline 混乱。
- 段落之间用**空行**分隔（否则会被视为同一段）。
- 行内强调：`**加粗**`、`*斜体*`、`==高亮==`、`~~删除线~~`。**统一用 `**`/`*` 写法，不混用 `__`/`_` 变体**，保证风格一致。
- 列表：无序 `- `、有序 `1. `、任务 `- [ ]` / `- [x]`，可嵌套（缩进）。
- 代码：行内 `code`；块代码用 ``` ``` ``` 包裹，可加语言标识（如 ```python）。
- 表格：竖线分隔、表头至少两个连字符。
- 引用：行首 `> `。
- 注释：`%% 注释内容 %%`（仅编辑视图可见，可用于给 LLM 或自己留批注）。
- 脚注（标注出处 / 待核实 / 补充说明，不打断正文）：
  ```markdown
  该版本号为 v2.3.1[^1]。

  [^1]: 来源：○○官网 2026-09-09。
  ```
  行内脚注可写作 `文字^[脚注内容]`（注：行内脚注仅在阅读视图生效）。
- 特殊字符转义：`\*`、`\_`、`\#`、`` \` ``、`\|`（表内）等。
- **不要**在 HTML 标签（`<div>`、`<span>` 等）内写 Markdown 语法，Obsidian 不渲染。

## 五、Markdown 呈现注意

- 不要在笔记里谈论"AI 生成"、"LLM"等话题本身——保留用户关心的领域知识。
- 若文档较长，可用 `##` 分章节便于 Outline 导航。
- 数学公式用 LaTeX：行内 `$...$`、块级 `$$...$$`。
- 图表可用 Mermaid 代码块（flowchart、sequenceDiagram、timeline 等）。

### 写作约定速查（直接影响正文呈现，写笔记时一并遵守）

这些规则与「正文排版」语法互补，决定**写什么、怎么标**，来自 SKILL.md 的写作要求，在此集中便于同处查阅：

- **不谈 AI/LLM 话题本身**：保留领域知识，不把"用户让 AI 怎么讲"这类对话过程写进正文。
- **区分事实与推断**：
  - 对话明确给出 → 直接写，不加标记。
  - 由上下文推断 → 标注 `(推断)`，并简述推断依据。
  - 无法核实的外部事实 → 标注 `(待核实)`。
  - 外部事实若确实有出处，可在该事实旁用脚注或括号注明来源（如 `（来源：○○官网）`）。
- **易变事实标注日期**：涉及数量、版本、上线状态、进度等，写成 `……（as of YYYY-MM-DD）`，避免日后被误读为当前现状。
- **上下文不完整时降级**：信息缺失不要凭常识补全，用 `> [!warning] 信息不完整` 提示块标出缺什么、建议补充。
- **与旧笔记冲突时显式标注**：发现同一问题新旧说法不一致，用 `> [!warning] 与 [[旧笔记名]] 存在冲突` 提示块列出两种说法及其依据，不静默改写任何一方。
- **通俗解释取舍**：能新增理解路径的类比/举例才保留（可用 `> [!tip] 通俗理解` 提示块承载）；只是换说法的重复表达可略。篇内保持一种叙述基调。
- **风格要求本身不进笔记**："用户要求这样讲"是对话过程，不构成知识，不写入正文。

## 六、命名与组织建议

- 文件名即笔记标题，应语义化、唯一（避免与其它笔记重名，否则双链会歧义）。
- 分类（子目录）命名简洁，如 `示例分类`、`Obsidian`、`运维经验`。
- 分类目录文件固定命名 `00-分类索引.md`，置于目录开头，排序靠前。
