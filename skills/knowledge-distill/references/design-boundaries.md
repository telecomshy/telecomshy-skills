# 设计边界（明确不做的事）

本文件记录**刻意不做**的功能及理由，作为后续迭代的护栏，避免重复讨论或范围蔓延。新增功能前先读本文件。

**暂缓（达到触发条件再做）**：

| 事项 | 暂缓理由 | 触发条件 |
| ---- | -------- | -------- |
| 操作日志 `log.md`（每次操作追加记录） | 增加维护动作，当前笔记量小、追溯需求弱 | 笔记超过约 30 篇，或出现"想不起什么时候记的"时 |
| 修正全库清扫（同一事实被修正后批量改写其它笔记） | 需语义搜索 + 多文件批量改写，工程量大，个人库规模下收益有限 | 同一事实被 3 篇以上笔记复述、且确需统一修正时 |
| `stale_index` 改用内容依据（而非文件 mtime） | mtime 会被 git checkout / 复制刷新而误报；改用内容哈希需引入状态文件或变更索引格式，成本较高 | 出现频繁误报、或笔记量增大到 mtime 不再可靠时 |

> 注：原暂缓项「`search-notes` 结果排序」**已实现**——检索结果现按「标题命中优先 → 命中次数多 → 日期新」确定性排序（见 SKILL.md「检索已有笔记」），不再列为暂缓。

**明确不做**：

| 事项 | 不做的理由 |
| ---- | ---------- |
| 向量 / 语义检索 | 生产验证结论：在 5-10 万 token 的笔记规模下，关键词 + 读取比向量检索更可靠、更可解释，且无额外依赖 |
| 跨工具兼容（适配多种 Agent 平台） | 本技能定位为 TeleAgent 单平台，跨平台适配会引入大量兼容分支，收益与成本不匹配 |
| 来源哈希追踪 | 需要维护哈希表、内容一变即失效，个人笔记场景下追溯价值低 |
| 置信度数值评分 | 数值化置信度易被误读为精确度量；用 `(推断)` `(待核实)` 定性标注已足够 |
| 疑问的语义判重自动化 | 判断两条疑问是否"同一个意思"需要语义理解，脚本做不准也难解释；脚本只提供 `list-questions` 列出已有条目，由 LLM 比对后决定复用还是新增。（注：笔记间的「疑似重复」候选检测是**确定性**的，不涉及语义，与本条不冲突。） |
| 笔记文风偏好写入长期记忆 | 笔记文风应随内容与当次指令定；把"都写白话 / 都写严谨"固化成长期偏好，会与"笔记需与内容匹配"冲突。用户在**对话交互**层面的偏好由记忆系统负责，不由本技能固化笔记文风 |
| 自动 hooks / 定时任务（含"笔记库定期巡检"） | 属于平台（harness）层能力，不应写进技能。TeleAgent 已有定时任务机制，技能保持"按需触发"即可；定期巡检若需要，由用户在对话里说一句"检查笔记库"手动触发（或自行在平台层配定时任务） |
| 来源与置信度的结构化字段（`source_date` / `source_type` / `source_ref` / `confidence`） | 与现有字段重复：`source_date`≈`created`、`source_type`≈`source`；`confidence` 数值化置信度与既有的 `(推断)` / `(待核实)` 定性标注重复；`source_ref` 仅在"外部资料接入"场景才有意义（该场景已不做）。再引入只会稀释写作注意力、增加歧义 |
| 外部资料 / 网页接入沉淀 | 本技能定位是"沉淀对话"；接入网页需额外处理抓取、去重、时效与版权，且市面已有成熟的抓取类技能，超出本技能定位 |

> **关于"搜索核验"与"不沉淀外部资料"的边界**：技能允许对**客观、易失效的外部事实**（版本号、数据、政策等）联网核验准确性并在笔记中标注出处（见 SKILL.md Step 5「外部事实首选核验」），但这**只是核验与出处标注，不是外部资料接入沉淀**——搜索到的网页/文档内容不会被整篇或大段摘录进笔记，笔记的知识来源仍是对话本身。二者不冲突。

**云存储后端（有道云笔记）**：

| 事项 | 说明 |
| ---- | ---- |
| 定位 | **可选、单账号、非镜像**能力：仅在 `format=youdao` 时启用；笔记正文只存有道云端，本地只留配置 / 草稿 / 滚动备份 |
| 与其它格式的关系 | 是 `format` 的第三个取值，**不影响** Obsidian / 普通 Markdown 的代码路径与行为；有道调用失败不阻断其它格式 |
| 降级 | 无原生标签、技能不写双链、无版本回退 API、检索只剩标题候选、lint 已支持（降级）、MOC 已移除；详见 `youdao-best-practices.md` 的「能力对照与降级」 |
| 依赖 | 官方 `youdaonote` CLI 与用户自备的 API Key（技能不存储 Key）；"未确认接口不实现"的护栏同样适用 |
| 不做 | 不直连 MCP、不驱动桌面端、不自动申请 Key、不做跨账号 / 多租户 |
